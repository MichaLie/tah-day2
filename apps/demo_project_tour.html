Project Tour — AI Vocabulary Flashcards

What was asked, what was built, how it works, and how you can change it yourself — written for a reader who doesn't code and will read this once.

1The brief that started it

"Using only sample_glossary.txt, build a single-file HTML flashcard quiz. No internet, no external libraries, no tracking; keyboard accessible; high-contrast; use the definitions verbatim. Propose a plan before writing. Afterwards, tell me how to test it." — followed by one fix: "Add a score summary explaining which answers were wrong and why."

2The plan that was approved

  1. Read the glossary; confirm it holds 10 term–definition pairs and flag anything ambiguous. (Nothing was.)
  2. Build one self-contained page with two modes: Browse (flip cards) and Quiz (4-option multiple choice built from the same 10 definitions).
  3. Add the requested fix: an end-of-quiz summary that explains every miss using the glossary's own wording.
  4. Self-check against the constraints (offline, keyboard, contrast), then hand over for the human test.

3What exists now

demo_flashcards.htmlThe whole app: content, appearance, and behaviour in one file. Open it in any browser — no installation, no internet.
sample_glossary.txtThe source of truth (on the course stick: lab_pack/sample_content/). The app's definitions were copied from here verbatim — if the two ever disagree, this file wins and the app needs updating.

4How it works — in plain language

Everything the app knows lives in one list near the bottom of the file, labelled TERMS. Each entry is a pair: a term, then its definition:

const TERMS = [ ["Generative AI","A field of AI in which algorithms trained on large amounts…"], ["Large Language Model (LLM)","A model trained to predict the next token…"], …8 more pairs… ];

That's the only part you'd ever need to touch. Everything else — the flipping, the shuffling, the scoring — just reads from this list. Change the list, and every card and quiz question updates itself.

Browse mode shows a card and swaps its face when you click (term ↔ definition). Quiz mode picks a definition, offers the right term plus three decoys drawn from the same list, counts your score, and — the "one fix" — lists every miss at the end with the correct definition, so wrong answers become the study guide.

5Change it yourself — three recipes

Fix a definition

  1. Right-click the file → Open With → TextEdit (Mac) or Notepad (Windows).
  2. Search (Ctrl/Cmd-F) for a few words of the term, e.g. Hallucination.
  3. Edit the text between the quotation marks after the comma. Save. Reload the page in your browser.
⚠️ Keep the quotation marks and the comma exactly as they are — they're the packaging. If the page goes blank, you deleted one; undo (Ctrl/Cmd-Z), save again.

Add an 11th card

  1. Copy one full line of the TERMS list — from [ to ],.
  2. Paste it on a new line inside the list and change both texts.
  3. Save, reload — browse and quiz pick it up automatically.

Make it yours

  1. Replace all 10 pairs with terms from your course (or better: give your agent your own glossary file and this brief).
  2. Update the footer so the source filename is right.
  3. Retest before students see it — you're the publisher.

6How it was verified

  • All 10 definitions compared word-for-word against sample_glossary.txt.
  • Opened with wifi off — works; no external requests, no fonts, no trackers, nothing collected.
  • Completed a full quiz round using only the keyboard (Tab, Enter, arrows, Space).
  • Tried to break it: double-clicks mid-question, phone-width window, replaying — no dead ends found.
  • Left for the human: the pedagogical judgment — are these the right 10 terms to drill at all?

7Where to take it next

Ask your agent for one change at a time: a "hard mode" that hides three decoys from related terms · a printable one-page glossary generated from the same list · a version in your language. And keep the habit that produced this page: "…and update the project tour to match."
